# Codex Pet Playground（ローカル読み込み版）

Codex Pet のスプライトシート（`pet.json` + `spritesheet.webp`）を、端末から読み込んで
ブラウザ内だけで再生・確認できる静的Webアプリ。

## 🔒 外部送信は一切発生しません

- 読み込んだ `pet.json` と `spritesheet.webp` は **サーバーへアップロードされません**。
- `fetch` / `XMLHttpRequest` / フォーム送信を一切使用していません。処理はすべて
  `FileReader` と `URL.createObjectURL` によるブラウザ内メモリ上の変換・描画のみです。
- 外部CDN・Webフォント・アナリティクス等の読み込みもありません。`index.html` 1ファイルに
  HTML/CSS/JavaScriptが完結しています。
- ページ上部にも同内容のバッジを常時表示しています。ブラウザの開発者ツールの
  Networkタブを開いた状態でファイルを読み込めば、通信が発生しないことを確認できます。
- ページを閉じる・再読み込みすると、読み込んだ内容はすべて破棄されます（保存機能なし）。

## 使い方

1. `index.html` をブラウザで開く（ローカルの `file://` でも、簡易HTTPサーバー経由でも可）。
2. 次のいずれかで読み込む。
   - **ファイルを選択**: `pet.json` と `spritesheet.webp` をまとめて選択、またはドラッグ＆ドロップ
   - **フォルダを選択**: ペットのフォルダごと指定すると、中の `pet.json` と `.webp` を自動で拾う
3. 画像サイズから v1 / v2 を自動判定し、情報パネル・アニメーション再生・16方向確認UIが有効になる。

### タイトルの決まり方

読み込んだ内容からページタイトル（タブ・画面ヘッダー）を自動で設定する。優先順位は次の通り。

1. `pet.json` の `name`
2. `pet.json` の `displayName`（旧表記の後方互換）
3. フォルダ選択時のフォルダ名
4. 既定タイトル

### ローカルでの起動例

ビルド工程は不要。任意の静的サーバーで配信すればよい。

```bash
git clone https://github.com/kazukibass/codex-pet-playground
cd codex-pet-playground
python3 -m http.server 8000
# ブラウザで http://localhost:8000/ を開く
```

`file://index.html` を直接開いても動作するが、ブラウザによっては `file://` 経由の
`<input type="file">` に一部制限がある場合があるため、動作確認は簡易HTTPサーバー経由を推奨する。

## 対応スプライト規格

| 規格 | 画像サイズ | グリッド | 用途 |
| --- | --- | --- | --- |
| v1 | 1536×1872 | 8列×9行 | 標準9動作。モバイル互換優先 |
| v2 | 1536×2288 | 8列×11行 | 標準9動作＋16方向の視線・向き |

セルサイズは共通で 192×208px。画像サイズがどちらにも一致しない場合は、
高さをセル高さ（208px）で割った行数で推定表示し、警告を表示する。

標準9行の割り当て：

| 行 | 状態 |
| ---: | --- |
| 0 | idle |
| 1 | running-right |
| 2 | running-left |
| 3 | waving |
| 4 | jumping |
| 5 | failed |
| 6 | waiting |
| 7 | running / active work |
| 8 | review |

v2のみ、行9・行10に8コマずつ、合計16方向を格納（未使用セルは透過想定）。
**方位の並び順（N始点・時計回り、行9→行10）はこのプレイグラウンド側の仮定であり、
Codex Pets本体の正式な並び順が別にある場合は一致しない可能性がある。** 16方向確認UIは
実際のアセットを目視で確認する用途に使う。

## 機能

- pet.json / spritesheet.webp の端末読み込み（ファイル選択・フォルダ選択・ドラッグ＆ドロップ／アップロードなし）
- v1 / v2 の自動判定（画像サイズから判定、不一致時は推定＋警告）
- `pet.json` の `name` からタイトルを自動設定（フォルダ名フォールバックあり）
- 再生速度の調整（0.25x〜3.0x）
- 背景色の変更（透過チェッカー／プリセット／カスタムカラー）
- 拡大縮小・パン・**フィット**（後述）
- v2のみ：16方向の視線を個別に確認
- モバイル互換トグル：v2画像でも標準9行（v1相当）だけで再生し、16方向データを無視する。
  タッチ端末では初期状態でON。手動でいつでも切り替え可能。

### UIモード

タッチ端末かどうか（`pointer: coarse`）で自動的に切り替わる。ヘッダーのボタンで手動切替も可能。

**通常UI（PC）** — 従来どおりのパネル縦積み。9種類のアニメーションをボタンで切り替え、
v2の16方向はコンパスUIから選ぶ。

**アケコンUI（タッチ端末）** — 画面下部にレバーとボタンを固定配置し、ビュワーを広く取る。

| 入力 | 動作 |
| --- | --- |
| レバー ニュートラル | idle |
| レバー ← / → | 走る（左）／走る（右）|
| レバー ↑ | ジャンプ |
| レバー ↓ | 待機 |
| ボタン A / B / C / D | 手を振る／失敗／作業中／レビュー |

- レバーとボタンは**同時操作できる**（Pointer Eventsでポインタごとに独立追跡）。
  レバーを倒したままボタンを連打できる。
- 押している間だけそのアニメーションをループ再生し、離すと idle に戻る。
- 方向が変わったタイミングで軽く振動する（`navigator.vibrate`。**iOS Safariは非対応**のため
  iOSでは視覚フィードバックのみ）。
- **16方向モード**（v2のみ）: レバーが16方向の視線選択に切り替わる。このモード中は
  レバーでの移動系は無効になり、視線の確認に専念する。ボタン4つは引き続き使える。
- PCでもキーボードで操作できる（矢印キー＝レバー、Z / X / C / V＝ボタンA〜D）。

**画面の向き**

- 縦画面: ビュワーの下にコントローラ。設定は下からのドロワーに格納。
- 横画面: 右側に設定パネルを常時表示。コントローラは既定でビュワーに重ねて配置し
  （レバー左端・ボタン右端）、狭い画面でも表示領域を確保する。設定の
  「横画面でコントローラをビュワーに重ねる」をOFFにすると縦積みに戻せるが、
  スマホ横持ちではビュワーが100px程度まで狭くなるため非推奨。

### 拡大縮小とフィット

キャラクターごとにセル内の占有幅が違うため、固定倍率だけでは大きすぎたり小さすぎたりする。
そこで次の3つを用意した。

- **ピンチズーム／ドラッグでパン**（PCではホイールズームとドラッグ）
- **表示サイズスライダー**（0.5x〜10x）
- **フィット**: 読み込み時に各行の非透過ピクセルのバウンディングボックスを計算しておき、
  「そのキャラが実際に占めている範囲」に合わせて自動でズーム＋センタリングする。
  アニメーションや向きを切り替えるたびに押し直せる。

なお `file://` で直接開いた場合、ブラウザによっては画素の読み取りが制限されて
バウンディングボックスを計算できないことがある。その場合フィットはセル全体に収める動作に
フォールバックする（簡易HTTPサーバー経由での利用を推奨）。

## 実装しなかったもの（今回のスコープ外）

- `.codex-pet.zip` の読み込み。ZIP展開ライブラリを同梱すれば実装可能だが、
  外部送信ゼロを守るためCDN不可・インライン埋め込みが必要になるため見送った。
  現状はフォルダ選択で同等のことができる。
- フォルダの**ドラッグ＆ドロップ**（`webkitGetAsEntry` による再帰読み込み）。
  フォルダはボタンからの選択のみ対応。ファイルのドロップは可能。
- PWA化（ホーム画面追加・オフラインキャッシュ）、常駐表示（PiP・ウィジェット・
  フローティング表示等）。

## 公開について

このリポジトリはビルド工程なしの静的ファイル（`index.html` 1枚）のみで構成されている。
GitHub Pages（Settings → Pages → Source: Deploy from a branch → `main` / `(root)`）や
Cloudflare Pages等、任意の静的ホスティングにこのリポジトリをそのまま配置すれば公開できる。
公開後も外部送信を行わない構成に変更はない。
